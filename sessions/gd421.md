## 一、已完成工作（Accomplished Work）

### 1. 架构解耦与外挂编排库搭建
- **创建外挂独立仓库**：建立 `mindscada-engine-ext`，完全解耦核心引擎与自研功能，不污染上游 Godot 源码树。
- **抽取 5 大自研核心模块**（从 `godot.4.2.1` 完整剥离并重构构建逻辑）：
  1. `varmanager`（变量管理器，OPC UA / open62541）
  2. `mqttmanager`（MQTT 通信，paho-mqtt-c）
  3. `kvmanager`（键值存储，MMKV）
  4. `qtwindow`（Qt 窗口嵌入驱动）
  5. `webview`（跨平台 Web 视图驱动：Windows WebView2 / Linux WebKit2GTK / 哑实现回退）
- **动态依赖解析与模块探测**：各模块重构 `SCsub`，按 `deps/{platform}_{arch}` → `MINDSCADA_DEPS_ROOT` → 本地环境 fallback 优先级自动探测依赖头文件与静态/动态库；未找到依赖时优雅告警并禁用，避免破坏整体编译。

### 2. 补丁集原子化与 OEM 定制资产迁移
- **提取 4.2.1 定制并迁移至 4.7.2 规范**（存放在 `patches/4.7.2/`）：
  - `0001-branding-splash-icons.patch`：OEM 品牌标识、Logo、启动 Splash 适配。
  - `0002-windows-version-metadata.patch`：Windows PE 可执行文件版本元数据、版权信息注入。
  - `0003-scene-editor-ext.patch`：场景与编辑器扩展逻辑适配。
  - `0004-crash-handler.patch`：崩溃处理与日志收集机制。
  - `0005-zstd-disable-asm.patch`：解决 x86_64 宿主机交叉编译 ARM 平台时 zstd 引用 x86 汇编循环符号未定义的链接错误（针对非 x86_64 追加 `ZSTD_DISABLE_ASM`）。
- **OEM 资源存放**：在 `patches/assets/` 中保存完整的品牌图标、矢量图及 Splash 图像。

### 3. 三大核心自动化脚本
- **`scripts/sync_upstream.py`**：
  - 自动克隆/检出指定版本的官方纯净 Godot 源码（默认 `4.7.2-stable`）。
  - 按序列无冲突应用 `patches/4.7.2/*.patch`。
  - 自动部署 OEM 视觉资产至引擎目录。
- **`scripts/build.py`**：
  - 统一跨平台构建驱动，替代原先分散且易出错的 `.bat` / `.sh`。
  - 自动配置编译器环境：Windows MSVC (`vswhere`/`vcvars64`)；Linux ARM32 (`arm-linux-gnueabihf-gcc/g++`)、ARM64 (`aarch64-linux-gnu-gcc/g++`)。
  - 自动挂载 `custom_modules`，注入版本宏，配置 SCons 构建缓存（默认 20 GiB 限制），支持 `--dry-run` 模拟。
- **`scripts/package.py`**：
  - 标准化产物打包工具，收集 `bin/` 生成物：
    - Windows x64 Editor：`MindStudio_v4.7.2_Windows_x86_64.zip`（含 `WebView2Loader.dll`、Console 包装器与说明文档）。
    - Windows x64 模板：`MindSCADA_v4.7.2_export_templates_windows.tpz`（含 `version.txt`，符合 Godot 模板管理器规范）。
    - Linux ARM32 模板：`MindSCADA_v4.7.2_export_templates_pi32.tpz`（树莓派 32 位）。
    - Linux ARM64 模板：`MindSCADA_v4.7.2_export_templates_pi64.tpz`（树莓派 64 位）。
    - SHA256 校验和清单：`dist/checksums.sha256`。

### 4. GitHub Actions CI/CD 流水线与矩阵编译调试
- **配置文件**：`.github/workflows/build-matrix.yml`。
- **跨平台矩阵**：
  - `windows-x64` (`windows-latest`)：构建 editor、template_debug、template_release。
  - `linux-arm32` (`ubuntu-latest`)：通过 `gcc-arm-linux-gnueabihf` 交叉编译 template_debug、template_release。
  - `linux-arm64` (`ubuntu-latest`)：通过 `gcc-aarch64-linux-gnu` 交叉编译 template_debug、template_release。
- **重大关键 Bug 修复记录**：
  1. **Zstandard 汇编跨架构符号缺失**：Host Linux x86_64 编译 ARM 目标时，SCsub 判定不编译 `huf_decompress_amd64.S`，但 `huf_decompress.c` 宏判定启用了汇编，导致 `HUF_decompress4X1_...` 符号未定义。制作并合入 `0005-zstd-disable-asm.patch` 彻底解决。
  2. **SCons 命令行宏注入大小写兼容**：Godot 4.7.2 SConstruct 忽略大写 `CCFLAGS`/`CXXFLAGS`，更新为 lowercase `ccflags`/`cxxflags`/`cppdefines`。
  3. **ARM 交叉编译器缺失导致的非法 CPU 指令错误**：ARM32 构建出现 `g++: error: unrecognized command-line option '-mfpu=neon-fp-armv8'`，原因是 SCons 默认使用了原生 x86_64 g++。在 `build.py` 中显式指定 `CC=arm-linux-gnueabihf-gcc` / `CXX=arm-linux-gnueabihf-g++`（ARM64 同理对应 `aarch64-linux-gnu-*`），彻底解决编译失败。
  4. **Private 仓库 Actions 免费额度耗尽拦截**：识别到由于 Private 仓库配额耗尽导致任务秒挂（`The job was not started because recent account payments have failed...`），协同用户将仓库改为 Public 后配额限制解除。
